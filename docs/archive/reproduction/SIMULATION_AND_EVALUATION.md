# Hopper 动画、训练与评估

训练读取固定数据集，用动作 MSE 更新模型；训练更新本身不调用 Hopper 收集数据。评估固定模型参数，把预测动作交给 MuJoCo，累计真实仿真奖励。评估轨迹不会加入训练集。

## 更新次数不是仿真步数

`num_steps_per_iter=10000` 表示每轮做 10000 次梯度更新，然后评估；不是 Hopper 跳跃 10000 步。当前官方入口每个目标评估 100 回合，Hopper 默认有 3600 和 1800 两个目标。评估间隔是配置选择，任何已保存的权重都可以独立评估。

`experiment_observed.py` 每轮保存 checkpoint、全部评估轨迹，并默认渲染每个目标首回合的 GIF。在 TensorBoard 的 Images 中查看 `simulation/target_3600/first_episode`，切换 step 比较不同训练阶段。磁盘动画在运行目录的 `videos/`。`--no_video` 关闭渲染；`--video_stride` 默认 4，表示每 4 个仿真步取一帧。动画从实际记录的物理状态渲染，不额外执行策略或环境步。

## Hopper 好坏怎么判断

本机 Gym 0.18.3 的默认 Hopper-v3 每步奖励为：前进速度 + 1 - 0.001 × 动作平方和。它鼓励向前跳跃、保持健康并减少控制代价，因此仅仅站得久不足以代表好策略。

身体高度不大于 0.7、躯干角度超出 (-0.2, 0.2)，或其他健康条件失败时会终止；也可能在明显倒地之前结束。时间上限为 1000 个环境步，每步 0.008 秒，即最多 8 秒仿真时间。这与训练墙钟时间不同。

| 指标 | 用途 |
|---|---|
| 回报均值 | 策略实际任务效果的主要指标 |
| 回报标准差 | 不同评估回合是否稳定 |
| D4RL 标准化分数 | 按官方随机/专家参考回报转换，便于对照论文 |
| 回合长度 | 是否早早失稳，需结合前进和回报一起看 |
| 动作 MSE | 离线训练拟合情况，不能替代仿真效果 |
| 动画与逐步轨迹 | 检查运动方式、失败原因和 RTG 条件的实际作用 |

目标 RTG=3600 是输入给策略的期望，不是已实现回报。论文 Hopper-medium 的 67.6±1.0 是三个种子的标准化结果；单次评估的回合标准差与跨种子标准差不同。官方训练没有另建监督学习验证集；实际效果通过仿真回合评估，不能由此推断跨任务泛化。

## 随时评估已保存模型

在另一个 Bash/tmux 窗口运行，替换 checkpoint 路径：

```bash
cd /home/ubuntu/weight/decision-transformer-master
source reproduction/activate_official.sh
cd gym
python -u evaluate_checkpoint.py runs_observed/你的运行目录/checkpoints/iteration_0001.pt --target 3600 --episodes 1
```

输出在运行目录的 `evaluations/`，包含 summary.json、逐步轨迹和首回合 GIF。1 回合适合看动画；统计验证用 `--episodes 100`，并记录 seed、checkpoint、目标值，保持比较口径一致。这不会更新权重，也不影响训练进程的随机数状态，但同时运行会占用计算资源。

原版 `experiment.py` 没有保存 checkpoint 或物理轨迹，不能事后恢复旧进程中间模型的动画。新观测入口从启动时开始保存，不能接管旧进程。

## 当前旧实验的配置差异

实际进程命令使用 `--warmup_steps 10000`，与约定的论文值 100000 不同。保留其结果用于诊断，不能标为完全按论文配置的正式复现。新观测入口默认为 100000。未停止或修改旧进程。

## 验证记录

真实 CUDA/Hopper 对照测试通过：观测前后的动作、奖励和参数更新一致；GIF 和 TensorBoard 动画摘要成功生成。独立 checkpoint 评估也已运行成功。验证使用仅训练 4 次更新的小模型，仅用于检查记录功能，不代表正式实验性能。
